# 기본 프레임워크

- 상태: 초기 구현 기준. 카메라 방식은 게임 기획에 따라 변경 가능.
- 관련 구현 기록: [프레임워크 구현](../implementation/framework.md)

## 목적

새 게임의 C++ 시작점을 만들고 생명주기, 입력 처리, 카메라 제어를 분리한다.

## 요구사항

- `EntryPoint`를 게임 실행의 루트로 둔다.
- 공통 인터페이스는 `Init()`, `Update(double delta)`, `Release()`로 구성한다.
- 기존 복셀 데모를 사용하지 않는 별도 시작 씬을 만든다.
- VS Code의 기존 F7 빌드, F5 빌드 후 실행 흐름을 그대로 사용한다.

## 초기 카메라 조작

장르와 플레이어가 아직 정해지지 않았으므로 자유 이동 카메라를 임시 기본값으로 사용한다.

| 입력 | 동작 |
|---|---|
| 우클릭 유지 | 카메라 제어 시작, 커서 캡처 |
| 마우스 이동 | 시점 회전 |
| WASD | 카메라 기준 전후좌우 이동 |
| Q / E | 카메라 기준 하강 / 상승 |
| Shift | 이동 속도 3배 |
| 우클릭 해제 / Esc | 제어 종료, 커서 복원 |

## 완료 기준

- Godot 생명주기에 따라 Init, Update, Release가 실행된다.
- Init/Release를 반복해도 중복 노드나 잔여 입력이 생기지 않는다.
- 이동 속도가 프레임 수나 대각선 입력에 따라 증가하지 않는다.
- 창 포커스 상실과 게임 일시정지 시 커서를 돌려주고 입력을 비운다.
- 새 시작 씬과 C++ 입력·카메라가 실행된다.

## 후속 결정

플레이어 이동, 카메라 추적·충돌, 게임패드, 키 설정 UI와 저장 기능은 게임 기획 후 결정한다.
